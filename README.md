# ระบบใบรับรองแพทย์ — โรงพยาบาลดับเบิ้ลยู เมดิคอล

เว็บ static ล้วน (ไม่มี build step) + Supabase เป็นฐานข้อมูล/ระบบล็อกอิน

## โครงสร้าง

```
public/
  index.html   หน้าตรวจสอบสำหรับลูกค้า (เปิดจาก QR)  →  /?id=<HN>&k=<token>
  admin.html   ระบบหลังบ้านสำหรับเจ้าหน้าที่           →  /admin.html
  cert.js      ตัวเรนเดอร์ใบรับรอง (ใช้ร่วมกันทั้ง 2 หน้า) + CSS
  config.js    URL และ anon key ของ Supabase
vercel.json    ตั้ง framework = null (เว็บ static)
db/schema.sql  โครงฐานข้อมูล + RLS + ฟังก์ชันตรวจสอบสาธารณะ (รันไปแล้ว)
```

## ผลแล็บตรวจสอบได้ (ตั้งแต่ ก.ย. 2569)

จุดที่ทำให้ใบของเรา "พิสูจน์ได้ว่าตรวจจริง" ไม่ใช่แค่ "มีใบ":

1. **ข้อมูลห้องปฏิบัติการ** — เลขที่สิ่งส่งตรวจ (Lab No.), เลขฟิล์มเอกซเรย์,
   เวลาลงทะเบียน/เก็บสิ่งส่งตรวจ/เอกซเรย์/รายงานผล, ชื่อ + ท.น. ของนักเทคนิคการแพทย์ผู้รายงานผล
   เก็บในคอลัมน์ `lab` (jsonb) — กรอกในหน้า admin, เลข Lab No. กดออกอัตโนมัติได้ (`next_lab_no()`)
2. **รับรอง 3 ขั้น** — ① ทนพ. รับรองผลแล็บ → ② แพทย์รับรองผล → ③ ผนึกผล
   ลายเซ็นแพทย์บนใบพิมพ์จะขึ้นเมื่อผ่านขั้น ② แล้วเท่านั้น
3. **รหัสผนึกผล (seal)** — sha256 ของผลตรวจ + ข้อมูลแล็บ + รหัสผนึกของใบก่อนหน้า (ลูกโซ่ใน `cert_seal`
   ที่เขียนได้ผ่าน `seal_certificate()` เท่านั้น) พิมพ์ 10 หลักแรกบนใบ
   หน้าตรวจสอบคำนวณใหม่ทุกครั้งที่เปิด → บอกได้ว่าผลถูกแก้ย้อนหลังหรือไม่
4. **แก้ผลตรวจ = การรับรองหลุดทันที** — trigger `cert_a_unseal` ล้าง `confirmed_at`,
   `lab_verified_at`, `seal` ทุกครั้งที่ผลตรวจ/ข้อมูลแล็บ/ตัวตนผู้ตรวจเปลี่ยน ต้องรับรองใหม่ทั้งชุด
5. **ไฟล์ผลตรวจต้นฉบับ** — แนบรูปใบรายงานผลแล็บ / ฟิล์มเอกซเรย์ / PDF ได้หลายไฟล์ต่อใบ
   (bucket `cert-labs`) เก็บ sha256 ของทุกไฟล์ไว้ใน `lab.files` ซึ่งอยู่ในข้อมูลที่ถูกผนึก
   ลูกค้าที่สแกน QR เปิดดู/บันทึกไฟล์ได้ และหน้าตรวจสอบจะโหลดไฟล์มาคำนวณ sha256 ใหม่
   แล้วเทียบให้เห็นว่า "✓ ไฟล์ตรงกับที่ผนึกไว้" — ไฟล์ถูกสลับเมื่อไหร่รู้ทันที
6. **หน้าตรวจสอบของลูกค้า** — แสดงไทม์ไลน์การตรวจจริง ไฟล์ผลแล็บ และสถานะรหัสผนึกเหนือใบรับรอง

ใบเก่าที่ยังไม่มีข้อมูลแล็บจะพิมพ์ออกมาเหมือนเดิมทุกประการ (บล็อกแล็บจะไม่แสดง)

`db/migration-lab-seal.sql` รันบน Supabase แล้ว (17 ก.ย. 2569) — ทดสอบแล้วว่า
ผนึกผลได้, ตรวจจับการแก้ผลย้อนหลังได้ (`seal_ok = false`), ใบเก่า 16 ใบยังเปิดดูได้ตามปกติ

## ฟีเจอร์ในหน้า admin

- **เพิ่ม/แก้/ยกเลิกใบรับรอง** — เลขที่ใบ (HN) และ token QR ออกให้อัตโนมัติ
  รูปแบบ `<ปี พ.ศ. 2 หลัก>9<เลขรัน 7 หลัก>` (เช่น `6990000040`) รันต่อเนื่องทุกปี
- **นำเข้า Excel/CSV** — นำเข้าได้ครั้งละหลายรายการ
- **พิมพ์ใบรับรองเต็มพร้อม QR** — ปุ่ม "พิมพ์" (รายใบ) หรือ "พิมพ์ที่เลือก" (หลายใบ)
- **พิมพ์สติ๊กเกอร์ QR** — สำหรับแปะบนเอกสารที่พิมพ์จาก Word/แบบฟอร์มกระดาษเดิม
  QR แต่ละดวงชี้ไปที่ใบของคนนั้นโดยเฉพาะ (มี token) ไม่ใช่ลิงก์กลาง
- **รูปถ่ายผู้ตรวจ** — แนบได้ในฟอร์มเพิ่ม/แก้ไข แสดงบนใบพิมพ์และหน้าตรวจสอบ
- **ยืนยันข้อมูลถูกต้อง** — เจ้าหน้าที่/แพทย์กดยืนยันหลังตรวจสอบข้อมูลแล้ว
  หน้าตรวจสอบสาธารณะ (ที่เปิดจาก QR) จะแสดงว่าใบนี้ผ่านการยืนยันโดยใคร เมื่อไหร่
  หรือ "ยังไม่ได้รับการยืนยัน" ถ้ายังไม่มีใครกด — ให้หมอ/รพ./นายจ้างเช็กความถูกต้องได้ทันทีโดยไม่ต้องล็อกอิน
- **รายงาน** — ยอดออกใบต่อเดือน, แยกตามชนิดฟอร์ม, นายจ้างยอดสูงสุด, สถานะยืนยัน
- **Export Excel** — ปุ่ม "Export Excel" ในหน้ารายการ ดาวน์โหลดรายการที่กรองอยู่เป็น .xlsx
- **หลายบัญชีเจ้าหน้าที่** — เพิ่มผู้ใช้ได้จาก Supabase Dashboard →
  Authentication → Add user (Email + Password) ไม่ต้องแก้โค้ด ทุกใบที่สร้าง/แก้/ยืนยัน
  จะบันทึกว่าใครทำ (คอลัมน์ผู้ออกใบในตาราง + ประวัติการแก้ไข)

## ความปลอดภัย

- ตาราง `certificates` เปิดเฉพาะ role `authenticated` (RLS)
- หน้าลูกค้าเรียกผ่าน `verify_certificate(hn, token)` ซึ่งเป็น SECURITY DEFINER
  ต้องมี HN คู่กับ token ที่สุ่มไว้ถึงจะคืนข้อมูล และคืนเฉพาะฟิลด์ที่แสดงบนใบรับรอง
- **กันไล่เดาเลข HN**: ถ้า IP เดียวกันตรวจสอบผิด (ไม่พบใบ) เกิน 10 ครั้ง/นาที
  ระบบจะหยุดตอบทันทีโดยไม่ query ฐานข้อมูลต่อ — ทุกการเข้าดู (สำเร็จ/ล้มเหลว)
  บันทึกลงตาราง `cert_access_log`
- **ใบลาป่วย (`sick_leave`)**: หน้าตรวจสอบสาธารณะไม่แสดงอาการ/การวินิจฉัยโรค
  (ถูกซ่อนอัตโนมัติในฟังก์ชัน `verify_certificate` — แสดงเฉพาะในระบบหลังบ้าน/ใบพิมพ์จริง)
- anon ถูก revoke สิทธิ์บนตารางทั้งหมดแล้ว
- ทุกการเพิ่ม/แก้/ลบ บันทึกลง `cert_audit` อัตโนมัติผ่าน trigger (พร้อมผู้กระทำ `auth.uid()`)
- token ของใบเก่าที่ QR แจกไปแล้วก่อนหน้านี้ (12 ใบแรก) ยังคงเป็นค่าว่างตามเดิม
  เพื่อไม่ให้ QR ที่พิมพ์แจกไปแล้วเปิดไม่ขึ้น — ใบใหม่ทุกใบได้ token สุ่มอัตโนมัติ
